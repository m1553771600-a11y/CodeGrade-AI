## 4. 仓库解析官

### 输入契约

```yaml
input:
  artifact:  zip 包（或已落盘临时路径）
  languages: [python, java]           # 一期锁两种
  上限:
    upload_bytes: ≤200MB              # 只卡传输
    source_files: 不硬限，走分区      # 由 token 预算动态裁量
    token_budget: ≤60000 / 单次评审   # 真上限
  安全:
    - 防 zip 炸弹 / 路径穿越（解压前校验）
```

### 输出契约（三层分区中间表示）

```yaml
ParsedRepo:
  meta:
    repo_id, language, source_file_count, entry_files[], excluded_count
  focus_layer:            # 焦点层 → 逐行深评
    - { path, role, code, key_functions[], importance }
  structure_layer:        # 结构层 → 静态分析结果
    - { path, total_lines, class_count,
        funcs: [{name, lines, cyclomatic, params}],
        naming_issues[] }
  ignore_layer:           # 忽略层 → 只记统计
    { count, patterns[] }
  static_metrics:         # 全局硬指标（规则算出，不靠 LLM）
    - duplicated_blocks[]        # 重复块
    - max_cyclomatic             # 最大圈复杂度
    - giant_files[]              # >2000 行 → 标「疑似巨石」
```

### 边界规则

- **三层分区**（按重要度分层，非按大小截断）：
  - 焦点层：入口 + indegree Top-N + 业务核心目录，逐行深评。
  - 结构层：其余源码，静态分析，不逐行读。
  - 忽略层：node_modules / dist / vendor / 图片 / 生成物，直接排除。
- **代表集选择**：入口 + indegree Top-N + 业务核心目录，受 token 预算约束，装不下自动滑到结构层。
- **大文件处理**：单文件 >2000 行 → 标「疑似巨石文件」，函数级聚合深评（截入口 + 关键函数 + 结构签名），不硬塞全文，也不跳过。
- **小而多**：海量小文件 → 去重 + 代表性抽样。

## 5. 评分维度（满分 100）

| 维度 | 权重 | 数据来源 |
|---|---|---|
| 结构·模块化 | 20 | 目录树 + 焦点层 + 静态 |
| 健壮性·安全 | 20 | 焦点层 LLM + 静态 |
| 可维护·设计 | 20 | 焦点层 LLM（SOLID / DRY / 设计模式） |
| 复杂度·重复 | 15 | 静态规则（圈复杂度 / 重复块 / 函数行数） |
| 规范·风格 | 15 | 焦点层 + RAG 检索官方规范 |
| 可读·注释 | 10 | 焦点层 LLM |

**每维度统一产出**（对齐 resume DimensionScore 结构）：

```yaml
DimensionScore:
  dimension, score, weight,
  issues: [{file, line, severity, evidence, suggestion}]
```

## 6. RAG 数据来源与性能

- **定位**：为「规范·风格」维度提供可溯源判据 + 薄弱点推荐资料。
- **来源（只做官方文档，合规）**：
  - PEP / Python 官方文档（PSF License，可自由使用，保留出处）。
  - Google Style Guide（CC BY 3.0，需署名）。
  - MDN 不入库（CC-BY-SA 风险），用官方 JS/TS 文档替代。
  - 每条切片带 `来源URL + 语言 + 标题`，展示给原文链接。
- **低时延**：文档量小 → 不启用 BGE-Reranker（BGE-M3 直接取 top-K）+ Redis 缓存 + SSE 流式。
